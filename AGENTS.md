# Working on QUANTA

QUANTA is a personal scientific notebook for Apple Silicon, Windows, and a standalone GitHub Pages web build. Preserve the calm visual notebook as the default experience. The project is general-purpose: do not turn it into an ASTREA-specific tool.

## Product rules

- Local writes must finish before displaying a saved state. Keep unsaved drafts recoverable after failures.
- Use `.quanta` only for editable notebooks. PDF, PNG, SVG, Markdown, HTML, text, and TeX exports are separate deliverables.
- Use the existing small glass controls. Avoid dashboards, gradients behind document text, decorative metrics, stock hero sections, and unnecessary animation.
- Keep expensive work out of normal typing. Bundle editor fonts. Lazy-load export engines and browser TeX.
- Retain theme, accessibility, focus-mode, and economy-mode behavior.
- No environment file is required by the end user. Configure Google OAuth in the app UI. Never commit credentials, refresh tokens, passwords, or actual notebooks.
- Plugins run in workers and receive the documented, versioned API. Never execute plugin code in the main application window.
- Google Drive stores immutable notebook revisions; never replace notebook bytes in place. Preserve concurrent branches as conflict copies. Export replacement is a separate, explicitly selected action.
- Respect the existing repository audience. Do not change private source visibility to enable Pages. If the account cannot host private-repository Pages, discuss a separate public web-build repository.

## Layout

- `src/components/`: notebook UI and dialogs.
- `src/extensions/`: ProseMirror math nodes.
- `src/lib/`: interchange, export, save queue, web persistence, and web Drive adapter.
- `src-tauri/src/`: Rust storage, OAuth, immutable Drive sync, TeX, and command bridge.
- `docs/`: user, maintainer, file-format, compatibility, and plugin documentation.
- `scripts/`: pinned engine preparation, web asset preparation, and release helpers.
- `plugins/examples/`: installable `.qplugin` examples; generated by `scripts/package-plugins.mjs`.

## Verification

After substantive changes run:

```sh
npm ci
npm run check
npm run build
cd src-tauri
cargo test --no-default-features
cargo clippy --no-default-features -- -D warnings
cargo fmt --check
```

On a host with native build prerequisites, also run `cargo check` and build the platform installer. Native build jobs must succeed before the dependent GitHub Pages deployment job runs. CI runs real-browser editor tests where a supported browser is available. Report blocked checks and runtime tests honestly; a compile is not proof of successful Google authorization or macOS installation.

For releases, retain lockfiles and pinned TeX versions, package the core offline TeX cache, include platform artifacts and checksums, and never advertise unsigned installers as notarized. Use a concrete title and description on pull requests.
